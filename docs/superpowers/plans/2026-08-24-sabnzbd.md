# SABnzbd Deployment Plan

Usenet carries no ratio, no seedtime and no hit-and-run, so every release SABnzbd can serve is a
release that costs nothing to keep. This plan puts it in front of Sonarr and Radarr only, where
its coverage is strong and where the seedbox's ratio damage came from.

Scope: TV and film. Music stays on private trackers, because obscure FLAC back catalogue is
usenet's weakest category and Lidarr's grabs are exactly that. Lidarr keeps the seedbox.

## Blocking prerequisite

**A news server subscription.** SABnzbd is a downloader, not a source. altHUB tells it where an
article set lives; a provider delivers the articles. Without provider credentials the pod runs and
downloads nothing.

Pick one before Task 1. The choice sets retention, connection count and the secret's shape. Any
Tier-1 European or US provider works; retention above 3000 days and 20+ connections is the usual
baseline.

## Global constraints

- **No gluetun.** Usenet is a TLS connection to one provider, with no swarm and no peers to hide
  from. The qBittorrent VPN exists because torrents announce your address; SAB has nothing to
  announce. Skipping it removes the MTU and userspace-WireGuard complexity entirely.
- **Static resources, no VPA.** par2 repair and unpack are bimodal exactly like Jellyfin
  transcoding: idle for hours, then all cores. VPA would size the ceiling against the idle it just
  observed and throttle the repair. Follow `apps/jellyfin/values.yaml`, not the VPA default.
- **worker-01 only** (`homelab.io/media: "true"`). Repair and unpack are CPU-heavy and write
  every byte twice; the NFS server is the one node where the writes stay local. No toleration
  needed, the taint is gone.
- **uid/gid 1000**, so the arrs can hardlink completed downloads instead of copying them.
- **Server-side apply**, chart version managed by Renovate, no `latest` tags.

## Storage layout

Two volumes, deliberately different classes:

| Path | Class | Why |
|---|---|---|
| `/config` | `longhorn`, 2Gi | `sabnzbd.ini` plus a SQLite history database |
| `/incomplete` | `longhorn`, 100Gi | Assembly, par2 repair and unpack are random-IO heavy |
| `/data/downloads/usenet` | `nfs` | Completed output, same filesystem as the library |

**The split matters.** Putting `incomplete` on NFS sends every par2 block over the network twice
and turns repair into an NFS latency benchmark. Putting `complete` anywhere but the media share
breaks hardlinking on import and doubles the library's disk usage.

Size `incomplete` for the largest concurrent queue you expect, not the largest file. A 4K season
pack mid-repair holds the archive and the extracted copy at once.

## File structure

```
apps/sabnzbd/
  app.yaml               # app-template 5.1.0
  values.yaml
  config-pvc.yaml        # longhorn, with the rationale and recovery path
  incomplete-pvc.yaml    # longhorn
  infisical-secret.yaml  # provider credentials + SAB API key
  limitrange.yaml        # defaultRequest, no default CPU limit
  README.md              # provider, retention, why no VPA, why no gluetun
```

No `vpa.yaml`, for the bimodal reason above. State that in `values.yaml` where a reader looks for
it.

## Tasks

### Task 1: Secrets in Infisical

Add at path `/sabnzbd/` in project `homelab-ef-28`, environment `prod`: provider host, port,
username, password, connection count, and a generated SAB API key. Commit
`infisical-secret.yaml` copied from `system/monitoring-system/infisical-secret.yaml`.

Verify the secret lands before the deployment references it, or the pod crash-loops on a missing
key rather than telling you which one.

### Task 2: PVCs

Two manifests, each carrying its own rationale. `longhorn` binds `Immediate` and expands in
place, so no `sync-wave` warning applies and sizing is for today.

Durability comes from a backup, not the volume. SAB has no scheduled config backup of its own, so
this needs the `apps/cleanuparr/backup-cronjob.yaml` treatment: the SQLite online-backup API, not
`cp`. The `incomplete` volume needs no backup, it is scratch by definition.

### Task 3: App manifests

`values.yaml` with the linuxserver image, the node selector, static resources, both PVCs by
`existingClaim`, the NFS data mount, an HTTPRoute at `sabnzbd.nik-homelab.dev`, and Homepage
annotations in the `Media` group.

Set `resources.requests` high enough that the scheduler sees the repair load. A requestless
container is invisible to the scheduler, which is what overloaded worker-00.

### Task 4: SABnzbd's own configuration

UI work, invisible to git, so record it in the README:

- Server credentials from the secret, SSL on, connections at the plan's limit.
- Categories `tv` and `movies`, mapping to `/data/downloads/usenet/tv` and `.../movies`.
- **Direct Unpack off** if `incomplete` is tight; it needs room for both copies at once.
- Post-processing scripts: none. The arrs handle import.

### Task 5: Register as a download client in Sonarr and Radarr

Not Lidarr. Category per arr, matching the seedbox convention that stopped the arrs claiming each
other's downloads.

**`removeCompletedDownloads: true` is correct here**, unlike on the seedbox. Nothing is seeding,
so removing the queue entry after import costs nothing and prevents exactly the stuck-queue
pile-up the arr-queue alert now watches for.

Do not add SAB to unpackerr. SAB unpacks its own output; a second unpacker racing it corrupts the
result.

### Task 6: Re-enable altHUB

Turn RSS, automatic search and interactive search back on in Sonarr and Radarr. Leave them off in
Lidarr, which has no usenet client and no reason to want one.

Update `apps/rclone-seedbox/README.md`, which currently records altHUB as switched off pending
this work.

### Task 7: Verify

- A manual search in Sonarr returns altHUB results and grabs one.
- The download completes, repairs if needed, unpacks, and imports.
- `ls -li` shows the library file and the completed download sharing an inode.
- The queue clears rather than sitting at `importFailed`.

## Open questions

1. **Which provider?** Blocks Task 1.
2. **Disk budget for `incomplete`?** 100Gi is a guess sized for one 4K season pack under repair.
   worker-01 has 512GB NVMe with Longhorn replicas on top, so this is not free.
3. **Keep unpackerr at all?** It exists for the torrent path only. If usenet takes most of TV and
   film, its remaining job is small enough to question later, not now.

## Deliberately excluded

- **Lidarr integration.** Usenet coverage for the library that generated the hit-and-run warnings
  is poor. Adding it invites grabs that fail to match and queue items nobody wants.
- **VPN routing.** No peers, no exposure, no reason.
- **Cross-seed.** A separate project for the torrent side, unaffected by any of this.
