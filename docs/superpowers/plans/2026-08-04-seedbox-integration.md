# Seedbox Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pull completed downloads from a seedit4.me seedbox into the cluster's NFS media volume and wire Radarr, Sonarr, and Prowlarr to grab private-tracker releases on that seedbox instead of the local qBittorrent.

**Architecture:** A Kubernetes CronJob runs `rclone copy` over SFTP from the seedbox's `media` category directory into `/data/downloads/seedbox` on the existing NFS volume. Radarr and Sonarr gain the seedbox qBittorrent as a second download client with a remote path mapping, so Completed Download Handling hardlinks from NFS into the library. No privileged pods, no FUSE mounts, no changes to Radarr's or Sonarr's Helm values.

**Tech Stack:** bjw-s `app-template` 5.0.1 (`type: cronjob`), `rclone/rclone` container, sealed-secrets, Justfile + `jq` + Radarr/Sonarr/Prowlarr REST APIs.

**Design spec:** `docs/superpowers/specs/2026-08-04-seedbox-integration-design.md`

## Global Constraints

- Seedbox SFTP endpoint: `nl137.seedit4.me:2097`. No shell (ProFTPD `mod_sftp`), not chrooted.
- Seedbox qBittorrent WebUI: `https://203.nl137.seedit4.me/qbittorrent` — a **different host** to the SFTP endpoint, and served on a subfolder, so `urlBase` is required in the *arr.
- rclone **must** set `shell_type=none` and `disable_hashcheck=true`, or every transfer errors.
- Seedbox paths: base `/home/seedit4me/torrents/qbittorrent`; categories `media` and `ratio`; pre-existing incomplete dir `temp`.
- rclone source and the *arr remote path mapping use the **same** string — one path namespace.
- NFS server `192.168.30.194`, share `/mnt/storage`, mounted at `/data`. Never `local-path`.
- All Kubernetes manifests include explicit `resources.requests` and `resources.limits`.
- No `Ingress` — this app has no UI and needs no route.
- Secrets sealed via `secrets/registry.tsv` + `just seal`. Never commit plaintext.
- No `Co-Authored-By` lines in commits.
- ArgoCD auto-syncs `main`. Merge to main = deploy.


## Task 1: Sealed SFTP credential

**Files:**
- Modify: `secrets/.secrets` (gitignored — local only)
- Modify: `secrets/.secrets.example`
- Modify: `secrets/registry.tsv`
- Create: `apps/rclone-seedbox/sftp-creds.yaml` (generated by `just seal`)

**Interfaces:**
- Produces: SealedSecret `rclone-seedbox-sftp` in namespace `rclone-seedbox`, with keys `RCLONE_CONFIG_SEEDBOX_USER` and `RCLONE_CONFIG_SEEDBOX_PASS` — consumed by Task 2's `values.yaml` via `envFrom`.

rclone reads remote definitions from environment variables named
`RCLONE_CONFIG_<REMOTE>_<OPTION>`, so no rclone config file is needed anywhere. Only the
username and password are secret; host, port, and the two shell-less settings are plain env in
Task 2.

- [ ] **Step 1: Obscure the SFTP password**

rclone will not accept a plaintext password in config. Obscure it locally:

```bash
rclone obscure 'YOUR_SEEDBOX_SFTP_PASSWORD'
```

Expected: a single base64-ish line, e.g. `hK9x2mQ...`. Copy it.

- [ ] **Step 2: Add the plaintext values to `secrets/.secrets`**

Append:

```bash
SEEDBOX_SFTP_USER=seedit4me
SEEDBOX_SFTP_PASS_OBSCURED=<output of step 1>
SEEDBOX_QBT_URL=https://203.nl137.seedit4.me/qbittorrent
SEEDBOX_QBT_USER=<qBittorrent WebUI username>
SEEDBOX_QBT_PASS=<qBittorrent WebUI password>
```

`SEEDBOX_QBT_*` are used by Task 3, not sealed into any manifest — the *arr store the
credential in their own configs.

**The WebUI host and the SFTP host are deliberately different.** SFTP is
`nl137.seedit4.me:2097`; the WebUI is `https://203.nl137.seedit4.me/qbittorrent`. Do not
"correct" either to match the other. Task 3 derives host `203.nl137.seedit4.me`, port `443`,
`useSsl: true`, and `urlBase: /qbittorrent` from this URL, and uses that same host for the
remote path mapping — which is right, because the mapping keys on the host the download client
connects to.

- [ ] **Step 1: Create `apps/rclone-seedbox/app.yaml`**


- [ ] **Step 2: Create `apps/rclone-seedbox/values.yaml`**

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/bjw-s-labs/helm-charts/main/charts/library/common/values.schema.json
controllers:
  main:
    type: cronjob
    cronjob:
      schedule: "*/15 * * * *"
      # Forbid: a run that overruns 15 minutes must not get a second copier
      # competing for the same files.
      concurrencyPolicy: Forbid
      successfulJobsHistory: 1
      failedJobsHistory: 3
      backoffLimit: 2
    containers:
      app:
        image:
          repository: rclone/rclone
          tag: 1.68.2
        command:
          - rclone
        args:
          - copy
          - seedbox:/home/seedit4me/torrents/qbittorrent/media
          - /data/downloads/seedbox
          - --transfers=4
          - --checkers=4
          - --stats=1m
          - --stats-one-line
          - --log-level=INFO
        env:
          # rclone builds the "seedbox:" remote from these. The username and
          # password come from the sealed secret via envFrom below.
          RCLONE_CONFIG_SEEDBOX_TYPE: sftp
          RCLONE_CONFIG_SEEDBOX_HOST: nl137.seedit4.me
          RCLONE_CONFIG_SEEDBOX_PORT: "2097"
          # ProFTPD mod_sftp serves SFTP with no login shell. Without these two,
          # rclone probes for a remote shell and runs md5sum over it, failing
          # every transfer.
          RCLONE_CONFIG_SEEDBOX_SHELL_TYPE: none
          RCLONE_CONFIG_SEEDBOX_DISABLE_HASHCHECK: "true"
        envFrom:
          - secretRef:
              name: rclone-seedbox-sftp
        resources:
          requests:
            cpu: 50m
            memory: 128Mi
          limits:
            cpu: 1
            memory: 512Mi

persistence:
  data:
    type: nfs
    server: 192.168.30.194
    path: /mnt/storage
    globalMounts:
      - path: /data
```

## Task 3: wire-seedbox Justfile recipe

**Files:**
- Modify: `Justfile` (add `wire-seedbox` after the `wire-media` recipe)

**Interfaces:**
- Consumes: `SONARR_API_KEY`, `RADARR_API_KEY`, `PROWLARR_API_KEY` from `secrets/.secrets.generated`; `SEEDBOX_QBT_URL`, `SEEDBOX_QBT_USER`, `SEEDBOX_QBT_PASS` from `secrets/.secrets` (Task 1).
- Consumes: `/data/downloads/seedbox` populated by Task 2.
- Produces: Prowlarr tag `seedbox`; one qBittorrent download client named `Seedbox` in each of Radarr and Sonarr, category `media`, tagged `seedbox`; one remote path mapping per *arr.

This follows the existing `wire-media` pattern exactly: `kubectl wait`, port-forward, poll with
`nc -z`, then idempotent `curl` + `jq` against the REST APIs.

- [ ] **Step 1: Add the recipe to `Justfile`**

Insert after the `wire-media` recipe:

```just
# Configure the seedbox qBittorrent as a second download client in Radarr/Sonarr,
# with a remote path mapping, and create the Prowlarr tag that routes to it.
wire-seedbox:
    #!/usr/bin/env bash
    set -euo pipefail
    source secrets/.secrets
    source secrets/.secrets.generated
    PF_PIDS=()
    cleanup() { for p in "${PF_PIDS[@]}"; do kill "$p" 2>/dev/null; done; }
    trap cleanup EXIT

    # Split SEEDBOX_QBT_URL into the host / urlBase / ssl fields the *arr expect.
    # Shared seedbox slots serve qBittorrent on a subfolder behind HTTPS, so
    # urlBase is required — leaving it empty is the usual "looks right, won't
    # connect" failure.
    QBT_HOST=$(echo "$SEEDBOX_QBT_URL" | sed -E 's#^https?://##; s#/.*$##')
    QBT_BASE=$(echo "$SEEDBOX_QBT_URL" | sed -E 's#^https?://[^/]+##; s#/$##')
    case "$SEEDBOX_QBT_URL" in
      https://*) QBT_SSL=true;  QBT_PORT=443 ;;
      http://*)  QBT_SSL=false; QBT_PORT=80  ;;
      *) echo "SEEDBOX_QBT_URL must start with http:// or https://" >&2; exit 1 ;;
    esac
    echo "Seedbox qBittorrent: host=$QBT_HOST port=$QBT_PORT ssl=$QBT_SSL urlBase='$QBT_BASE'"

    echo "Waiting for Sonarr, Radarr, Prowlarr pods to be ready..."
    kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=sonarr   -n sonarr   --timeout=60s
    kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=radarr   -n radarr   --timeout=60s
    kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=prowlarr -n prowlarr --timeout=60s

    echo "Port-forwarding Sonarr, Radarr, Prowlarr..."
    kubectl port-forward -n sonarr   svc/sonarr   8989:8989 &
    PF_PIDS+=($!)
    kubectl port-forward -n radarr   svc/radarr   7878:7878 &
    PF_PIDS+=($!)
    kubectl port-forward -n prowlarr svc/prowlarr 9696:9696 &
    PF_PIDS+=($!)
    for i in $(seq 1 20); do
      nc -z localhost 8989 && nc -z localhost 7878 && nc -z localhost 9696 && break
      sleep 0.2
    done

    SONARR="http://localhost:8989"
    RADARR="http://localhost:7878"
    PROWLARR="http://localhost:9696"

    REMOTE_PATH="/home/seedit4me/torrents/qbittorrent/media"
    LOCAL_PATH="/data/downloads/seedbox"

    ensure_tag() {
      local url="$1" api_key="$2" api_ver="$3" label="$4"
      local id
      id=$(curl -sf -H "X-Api-Key: $api_key" "$url/api/$api_ver/tag" \
        | jq -r --arg l "$label" '(.[] | select(.label == $l) | .id) // empty')
      if [ -z "$id" ]; then
        id=$(curl -sf -X POST -H "X-Api-Key: $api_key" -H "Content-Type: application/json" \
          "$url/api/$api_ver/tag" -d "$(jq -n --arg l "$label" '{label:$l}')" | jq -r '.id')
        echo "tag created: $label (id=$id)" >&2
      else
        echo "tag exists: $label (id=$id)" >&2
      fi
      echo "$id"
    }

    ensure_download_client() {
      local url="$1" api_key="$2" label="$3" tag_id="$4"
      if curl -sf -H "X-Api-Key: $api_key" "$url/api/v3/downloadClient" \
          | jq -e --arg n "Seedbox" 'any(.[]; .name == $n)' >/dev/null 2>&1; then
        echo "$label download client: already configured"
        return
      fi
      # seedCriteria intentionally omitted: qBittorrent's global seeding limit
      # governs deletion. Setting it here would override that per-torrent and
      # risk deleting before TorrentLeech's 10-day class minimum.
      curl -sf -X POST -H "X-Api-Key: $api_key" -H "Content-Type: application/json" \
        "$url/api/v3/downloadClient" -d "$(jq -n \
          --arg host "$QBT_HOST" --arg base "$QBT_BASE" \
          --arg user "$SEEDBOX_QBT_USER" --arg pass "$SEEDBOX_QBT_PASS" \
          --argjson port "$QBT_PORT" --argjson ssl "$QBT_SSL" --argjson tag "$tag_id" \
          '{
            name: "Seedbox",
            implementation: "QBittorrent",
            configContract: "QBittorrentSettings",
            protocol: "torrent",
            enable: true,
            priority: 1,
            removeCompletedDownloads: false,
            removeFailedDownloads: true,
            tags: [$tag],
            fields: [
              {name:"host",     value:$host},
              {name:"port",     value:$port},
              {name:"useSsl",   value:$ssl},
              {name:"urlBase",  value:$base},
              {name:"username", value:$user},
              {name:"password", value:$pass},
              {name:"category", value:"media"}
            ]
          }')" > /dev/null
      echo "$label download client: created"
    }

    ensure_path_mapping() {
      local url="$1" api_key="$2" label="$3"
      if curl -sf -H "X-Api-Key: $api_key" "$url/api/v3/remotePathMapping" \
          | jq -e --arg h "$QBT_HOST" --arg r "$REMOTE_PATH" \
            'any(.[]; .host == $h and .remotePath == $r)' >/dev/null 2>&1; then
        echo "$label remote path mapping: already configured"
        return
      fi
      curl -sf -X POST -H "X-Api-Key: $api_key" -H "Content-Type: application/json" \
        "$url/api/v3/remotePathMapping" -d "$(jq -n \
          --arg h "$QBT_HOST" --arg r "$REMOTE_PATH/" --arg l "$LOCAL_PATH/" \
          '{host:$h, remotePath:$r, localPath:$l}')" > /dev/null
      echo "$label remote path mapping: created"
    }

    PROWLARR_TAG=$(ensure_tag "$PROWLARR" "$PROWLARR_API_KEY" v1 seedbox)
    RADARR_TAG=$(ensure_tag "$RADARR" "$RADARR_API_KEY" v3 seedbox)
    SONARR_TAG=$(ensure_tag "$SONARR" "$SONARR_API_KEY" v3 seedbox)

    ensure_download_client "$RADARR" "$RADARR_API_KEY" Radarr "$RADARR_TAG"
    ensure_download_client "$SONARR" "$SONARR_API_KEY" Sonarr "$SONARR_TAG"

    ensure_path_mapping "$RADARR" "$RADARR_API_KEY" Radarr
    ensure_path_mapping "$SONARR" "$SONARR_API_KEY" Sonarr

    echo ""
    echo "Manual step remaining — Prowlarr UI:"
    echo "  Tag the IPTorrents and TorrentLeech indexers with 'seedbox' (id=$PROWLARR_TAG)."
    echo "  Releases from tagged indexers then route to the Seedbox download client;"
    echo "  everything else keeps using the local qBittorrent behind gluetun."
```

## Task 4: Seedbox configuration and end-to-end verification

**Files:** none — this task is seedbox-side UI configuration plus verification of the whole
chain. It is a separate task because it is the gate that must pass before auto-delete is
enabled, and getting the order wrong can delete content that never reached NFS.

**Interfaces:**
- Consumes: everything from Tasks 1–3.

- [ ] **Step 1: Set Torrent Management Mode to Automatic**

qBittorrent WebUI → Options → Downloads → **Default Torrent Management Mode: Automatic**.

In Manual mode qBittorrent ignores category save paths and uses the path supplied at add time —
the categories would look correct and place nothing where expected.

- [ ] **Step 2: Confirm the incomplete directory is unchanged**

Options → Downloads → **Keep incomplete torrents in** should already read
`/home/seedit4me/torrents/qbittorrent/temp`. Leave it enabled. This is what guarantees the
`media` directory holds only completed files, so `rclone copy` can never pull a half-written
file.

- [ ] **Step 3: Create the two categories**

Left sidebar → right-click **Categories** → Add category, twice:

| Name | Save path |
|------|-----------|
| `media` | `/home/seedit4me/torrents/qbittorrent/media` |
| `ratio` | `/home/seedit4me/torrents/qbittorrent/ratio` |

- [ ] **Step 4: Point autobrr at the `ratio` category**

autobrr → Filters → your filter → Actions → qBittorrent action: **Category: `ratio`**, client
pointed at localhost. Not at Radarr or Sonarr — ratio grabs must not be imported.

- [ ] **Step 5: Prefer freeleech in the autobrr filter**

autobrr → Filters → your filter → **Advanced → Freeleech: enabled**.

IPTorrents freeleech counts upload but not download, so under an account-wide ratio obligation
this raises ratio at zero ratio cost. It is the single highest-leverage setting available for the
stated goal, and it is one checkbox.

Also set a per-release **size ceiling** on the same filter so one oversized release cannot
consume the 1500 GB disk. The 10-day seeding floor caps sustainable intake at roughly
150 GB/day; a size ceiling alone does not enforce that, so revisit the filter if disk usage
climbs.

| Field | Setting |
|-------|---------|
| When ratio reaches | unchecked |
| When total seeding time reaches | unchecked |
| When inactive seeding time reaches | **checked, `14400`** |
| then | **Remove torrent and its content** |

`14400` minutes is 10 days — TorrentLeech's Registered-class minimum. The field defaults to
`1440` (one day); leaving it would cause a hit-and-run warning on every TL grab. "Remove
torrent" without "and its content" reclaims no disk. Re-read this if the TL user class changes —
TL God is 4 days.
