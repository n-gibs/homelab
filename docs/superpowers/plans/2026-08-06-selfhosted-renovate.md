# Self-hosted Renovate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Renovate as an in-cluster CronJob against `n-gibs/homelab`, replacing the hosted Mend app that never onboarded this repo.

**Architecture:** The official Renovate Helm chart deployed to `platform/renovate/`, discovered automatically by the platform ApplicationSet. The chart *is* a CronJob. Global config (which repo, which platform) lives in `values.yaml`; update rules stay in the repo's existing root `renovate.json`, untouched. Credentials come from one sealed secret mounted as `envFrom`.

**Tech Stack:** Helm chart `renovate` 46.251.0, image `ghcr.io/renovatebot/renovate:44.14.3`, ArgoCD, sealed-secrets, kubeseal.

**Spec:** `docs/superpowers/specs/2026-08-06-selfhosted-renovate-design.md`

## Global Constraints

- Chart version is exactly `46.251.0` from `https://docs.renovatebot.com/helm-charts`.
- Image tag is exactly `44.14.3`, overriding the chart's bundled appVersion `43.288.0`.
- Override **only** `image.tag`. Never set `image.registry` or `image.repository` — see Task 1.
- CronJob schedule is exactly `0 3,15 * * *`, timezone `America/Los_Angeles`.
- `renovate.config` is an inline **JSON string**, not a YAML map.
- Do **not** create `platform/renovate/vpa.yaml`. This workload is a documented exception to the repo's all-apps-get-VPA rule.
- Do **not** modify the root `renovate.json`. Its `"schedule": ["every weekend"]` stays as the PR gate.
- Do **not** create a namespace manifest — `bootstrap/root/templates/stack.yaml` sets `CreateNamespace=true`.
- Do **not** create a PrometheusRule. Existing cluster-wide CronJob alerts already cover this.
- Never commit `secrets/.secrets`. Only the sealed output is committed.
- Deploy by merging to `main` and letting ArgoCD sync. No manual `kubectl apply` of managed manifests.

## File Structure

| File | Responsibility |
|---|---|
| `platform/renovate/app.yaml` | Chart source. Parsed by Renovate's first custom manager for chart bumps. |
| `platform/renovate/values.yaml` | Schedule, image tag pin, global Renovate config, secret reference, resources. |
| `platform/renovate/renovate-env.yaml` | Sealed secret (generated by `just seal`, committed). |
| `secrets/registry.tsv` | One appended row describing the secret. |

### Task 1: Chart manifests with dry-run enabled

**Files:**
- Create: `platform/renovate/app.yaml`
- Create: `platform/renovate/values.yaml`

**Interfaces:**
- Consumes: nothing.
- Produces: a Helm release named `renovate` in namespace `renovate`, whose pod reads env vars from a secret named `renovate-env` (Task 2 creates it).

- [ ] **Step 1: Branch off main**

The current branch is `feat/cleanuparr` and carries unrelated work. Start clean:

```bash
git checkout main && git pull && git checkout -b feat/renovate-selfhosted
```

- [ ] **Step 2: Add the Helm repo locally so the chart can be rendered**

```bash
helm repo add renovate https://docs.renovatebot.com/helm-charts
helm repo update renovate
```

- [ ] **Step 3: Create `platform/renovate/app.yaml`**

```yaml
chartName: renovate
chartRepo: https://docs.renovatebot.com/helm-charts
chartVersion: 46.251.0
```

This matches the repo's first custom manager (`chartName` / `chartRepo` / `chartVersion` with the `helm` datasource), so chart bumps land in the existing `helm charts` PR group.

- [ ] **Step 4: Create `platform/renovate/values.yaml`**

```yaml
# renovate: datasource=docker depName=ghcr.io/renovatebot/renovate
image:
  tag: 44.14.3

cronjob:
  schedule: "0 3,15 * * *"
  timeZone: America/Los_Angeles
  # Two Renovate runs at once can open duplicate PRs for the same dependency.
  concurrencyPolicy: Forbid
  # k8s keeps only 1 failed pod by default; 3 gives enough log history to debug a bad run.
  failedJobsHistoryLimit: 3

existingSecret: renovate-env

renovate:
  config: |
    {
      "platform": "github",
      "onboarding": false,
      "repositories": ["n-gibs/homelab"],
      "dryRun": "full"
    }

# Temporary, removed in Task 4 along with dryRun. Required for verification:
# Renovate logs a malformed RENOVATE_HOST_RULES at debug level only, so at the
# default info level a silent credential failure is invisible.
env:
  LOG_LEVEL: debug

resources:
  requests:
    cpu: 200m
    memory: 512Mi
  limits:
    cpu: 1
    memory: 2Gi
```

**Why the image block is tag-only, and why this matters more than it looks.**
The chart splits `image.registry` (`ghcr.io`) from `image.repository` (`renovatebot/renovate`). Writing `repository: ghcr.io/renovatebot/renovate` renders `ghcr.io/ghcr.io/renovatebot/renovate`. Worse, the repo's second `values.yaml` matchString requires `repository:` *immediately* after `image:` — and since the chart orders the keys `registry`, `repository`, `tag`, any override including `registry` matches **neither** matchString. Renovate would then silently stop tracking its own version: no error, just a dependency that never updates. The tag-only form matches the first matchString. Step 6 proves it.

`"dryRun": "full"` is deliberate and gets removed in Task 4. It is a Renovate config option, so it belongs inside this JSON string, not as a chart value.

- [ ] **Step 5: Render the chart and verify the output**

```bash
helm template renovate renovate/renovate --version 46.251.0 \

  | grep -E 'kind:|schedule:|timeZone:|concurrencyPolicy:|image:|secretRef|name: renovate-env|LOG_LEVEL'
```

- [ ] **Step 6: Verify Renovate will track its own image tag**

This is the check that catches the silent-failure mode described in Step 4. Run from the repo root:

```bash
python3 - <<'EOF'
import json, re
cfg = json.load(open('renovate.json'))
vals = open('platform/renovate/values.yaml').read()
# Renovate uses (?<name>); Python needs (?P<name>)
py = lambda p: re.sub(r'\(\?<([A-Za-z]\w*)>', r'(?P<\1>', p)
hits = [h.groupdict()
        for m in cfg['customManagers'] if any('values' in f for f in m['fileMatch'])
        for p in m['matchStrings']
        for h in re.finditer(py(p), vals)]
assert len(hits) == 1, f"expected exactly 1 match, got {len(hits)}: {hits}"
assert hits[0] == {'datasource': 'docker',
                   'depName': 'ghcr.io/renovatebot/renovate',
                   'currentValue': '44.14.3'}, hits[0]
print("OK — Renovate tracks its own image:", hits[0])
EOF
```

Expected: `OK — Renovate tracks its own image: {'datasource': 'docker', 'depName': 'ghcr.io/renovatebot/renovate', 'currentValue': '44.14.3'}`

A failure here means the tag would never be updated, with no runtime error to tell you.

- [ ] **Step 7: Confirm no VPA and no namespace manifest were created**

```bash
ls platform/renovate/
```

Expected exactly: `app.yaml  values.yaml`

- [ ] **Step 8: Commit**

```bash

git commit -m "feat(renovate): self-hosted chart manifests, dry-run enabled
```

### Task 2: Sealed secret for GitHub and Docker Hub credentials

**Files:**
- Modify: `secrets/registry.tsv` (append one row)
- Create: `platform/renovate/renovate-env.yaml` (generated by `just seal`)

**Interfaces:**
- Consumes: the release from Task 1, which references `existingSecret: renovate-env`.
- Produces: a `SealedSecret` named `renovate-env` in namespace `renovate` with keys `RENOVATE_TOKEN` and `RENOVATE_HOST_RULES`. The chart mounts it via `envFrom.secretRef`, so both keys become environment variables.

- [ ] **Step 1: Create the fine-grained GitHub PAT**

This is a manual step in the GitHub UI — https://github.com/settings/personal-access-tokens

- Resource owner: your account. Repository access: **Only select repositories** → `n-gibs/homelab`.
- Permissions:

| Permission | Level | Why |
|---|---|---|
| Contents | Read and write | push update branches |
| Pull requests | Read and write | open and update PRs |
| Issues | Read and write | Dependency Dashboard |
| Metadata | Read-only | mandatory, auto-granted |

Do **not** grant `Workflows` — this repo has no `.github/workflows/`.

Note the expiry date; fine-grained PATs cap at one year and expiry presents as a 401 plus a `CronJobJobFailed` alert.

- [ ] **Step 2: Create a Docker Hub access token**

https://app.docker.com/settings/personal-access-tokens — **Public repo read-only** scope is sufficient. Note the Docker Hub *username* too; both are needed.

- [ ] **Step 3: Add both values to `secrets/.secrets`**

This file is gitignored and must never be committed. `secrets/seal.sh` `source`s it, so the JSON value must be single-quoted to survive shell parsing:

```bash
RENOVATE_TOKEN=github_pat_xxxxxxxxxxxxxxxxxxxx
RENOVATE_HOST_RULES='[{"hostType":"docker","matchHost":"https://index.docker.io","username":"YOUR_DOCKERHUB_USERNAME","password":"dckr_pat_xxxxxxxxxxxx"}]'
```

The JSON must be valid and must be an array. If it fails to parse, Renovate logs at `debug` level and continues with **no host rules at all** — silently falling back to anonymous, rate-limited Docker Hub pulls. Task 3 checks for this.

- [ ] **Step 4: Verify the JSON parses before sealing it**

```bash
bash -c 'source secrets/.secrets && echo "$RENOVATE_HOST_RULES"' | python3 -c "
import json,sys
v = json.load(sys.stdin)
assert isinstance(v, list), 'must be a JSON array'
assert v[0]['hostType'] == 'docker' and v[0]['username'] and v[0]['password']
print('OK — host rules parse as an array of', len(v), 'rule(s)')
"
```

Expected: `OK — host rules parse as an array of 1 rule(s)`

- [ ] **Step 5: Append the registry row**

Add to `secrets/registry.tsv` (columns are whitespace-separated: name, namespace, outfile, `key=ENVVAR` pairs):

```
renovate-env    renovate    platform/renovate/renovate-env.yaml    RENOVATE_TOKEN=RENOVATE_TOKEN,RENOVATE_HOST_RULES=RENOVATE_HOST_RULES
```

The key names and the env var names are identical here, which is why both sides look repetitive. That is correct — Renovate reads these exact variable names.

- [ ] **Step 6: Seal it**

```bash
just seal renovate-env
```

Expected: `Sealed: platform/renovate/renovate-env.yaml`

If this fails with a missing `pub-cert.pem`, run `just kubeseal-fetch-cert` first.

- [ ] **Step 7: Verify the sealed output is encrypted and correctly targeted**

```bash
grep -E "name:|namespace:|RENOVATE" platform/renovate/renovate-env.yaml
```

Expected: `name: renovate-env`, `namespace: renovate`, and both key names followed by long base64 ciphertext. Confirm **no plaintext token** appears — the values must not start with `github_pat_` or `dckr_pat_`, and no `[{"hostType"` should be visible:

```bash
grep -cE 'github_pat_|dckr_pat_|hostType' platform/renovate/renovate-env.yaml
```

Expected: `0`

- [ ] **Step 8: Commit**

```bash
git add secrets/registry.tsv platform/renovate/renovate-env.yaml
git commit -m "feat(renovate): sealed GitHub and Docker Hub credentials

Fine-grained PAT scoped to n-gibs/homelab only, rather than a classic
repo-scoped token whose blast radius is the whole account.

RENOVATE_HOST_RULES raises the Docker Hub rate limit for the 6 of 15
images in this repo that come from Docker Hub."
```

## Rollback

If Renovate misbehaves after going live, suspend it without deleting anything:

```bash
kubectl patch cronjob -n renovate renovate -p '{"spec":{"suspend":true}}'
```

This trips the existing `CronJobSuspended` alert, which is the intended reminder to either fix or remove it. A permanent removal is `git rm -r platform/renovate/` plus deleting the registry row, then merging.

## Out of Scope

- Self-hosted GitHub App identity.
- A dedicated PrometheusRule for Renovate.
- VPA for this workload.
- Persistent SQLite cache — enable only if Docker Hub rate limits appear despite the host rules.
- `GITHUB_COM_TOKEN` — add only if changelogs come back empty in PR bodies.
- Any change to the root `renovate.json`.
