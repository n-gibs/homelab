# Headlamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy Headlamp as a read-only Kubernetes web UI at `headlamp.nik-homelab.dev`, with
no login and no state.

**Architecture:** The upstream `headlamp/headlamp` chart, added to `apps/` so the root
ApplicationSet discovers it. The chart's native `httpRoute` carries both the Gateway API route
and the Homepage annotations. Authentication is off; the RFC1918 gateway VIP is the boundary.
RBAC is read-only: the chart binds built-in `view`, and a second ClusterRole adds read on every
non-core API group so CRDs are visible without exposing Secrets.

**Tech Stack:** Helm, ArgoCD, Gateway API (Envoy Gateway), VPA, blackbox-exporter.

**Spec:** `docs/superpowers/specs/2026-09-20-headlamp-design.md`

## Global Constraints

- Directory `apps/headlamp/`, namespace `headlamp`. The ApplicationSet derives both from the
  directory basename.
- Chart `headlamp` 0.45.0 from `https://kubernetes-sigs.github.io/headlamp/`.
- **Do not set `image.tag`.** An explicit tag survives Helm upgrades and decouples the running
  image from the chart version.
- `HTTPRoute` only. Never `Ingress`.
- No Secrets, no PVC, no backup CronJob. Headlamp holds no state.
- Manifest comments: the non-obvious why only, 4 lines maximum. Measurements and incident
  detail go in the commit message.
- Commit messages carry no attribution trailers, per the repo's hard rule.
- Branch `feat/headlamp`, already created off `main`.

## Validation model

The apps ApplicationSet tracks `revision: main` (`bootstrap/root/values.yaml`), so an
Application cannot be pointed at this branch to test it. Everything verifiable offline gets
verified before merge with `helm template` and server-side dry-runs. Live behavior is verified
after merge, in Task 5. Plan to fix forward.

Tasks 1 through 4 each end with a commit on `feat/headlamp`. Nothing reaches the cluster until
Task 5.

### Task 1: Chart source and values

**Files:**
- Create: `apps/headlamp/app.yaml`
- Create: `apps/headlamp/values.yaml`

**Interfaces:**
- Consumes: nothing.
- Produces: a Helm release named `headlamp` in namespace `headlamp`, rendering a Deployment,
  Service, ServiceAccount and HTTPRoute all named `headlamp`, plus a ClusterRoleBinding named
  `headlamp-admin` bound to `view`. Task 2 binds a second role to the same ServiceAccount.
  Task 3 targets the Deployment by name.

- [ ] **Step 1: Confirm the chart repo is available locally**

```bash
helm repo add headlamp https://kubernetes-sigs.github.io/headlamp/
helm repo update headlamp
helm search repo headlamp/headlamp -o yaml
```

Expected: `version: 0.45.0` and `app_version: 0.45.0`. If a newer version appears, stop and
re-read the chart's values before continuing. This plan is written against 0.45.0.

- [ ] **Step 2: Write `apps/headlamp/app.yaml`**

```yaml
chartName: headlamp
chartRepo: https://kubernetes-sigs.github.io/headlamp/
chartVersion: 0.45.0
```

No `syncWave`. Nothing depends on Headlamp, so the stack default is correct.

- [ ] **Step 3: Write `apps/headlamp/values.yaml`**

```yaml
# Read-only UI, no login: the gateway VIP is RFC1918, so the network is the
# boundary. Widening either of these without the other is the mistake to avoid.
clusterRoleBinding:
  clusterRoleName: view

config:
  unsafeUseServiceAccountToken: true
  oidc:
    # Defaults to true and creates an empty `oidc` Secret even when unused.
    secret:
      create: false

# The chart ships resources: {}, and a requestless container is invisible to
# the scheduler. No CPU limit: VPA preserves request:limit and would throttle.
resources:
  requests:
    cpu: 10m
    memory: 64Mi
  limits:
    memory: 256Mi

ingress:
  enabled: false

httpRoute:
  enabled: true
  hostnames:
    - headlamp.nik-homelab.dev
  parentRefs:
    - name: homelab
      namespace: envoy-gateway-system
  annotations:
    gethomepage.dev/enabled: "true"
    gethomepage.dev/name: "Headlamp"
    gethomepage.dev/description: "Kubernetes cluster UI"
    gethomepage.dev/group: "Infrastructure"
    gethomepage.dev/icon: "headlamp.png"
    gethomepage.dev/href: "https://headlamp.nik-homelab.dev"
```

- [ ] **Step 4: Render and assert every offline check at once**

```bash
helm template headlamp headlamp/headlamp \
  --namespace headlamp \
  -f apps/headlamp/values.yaml > /tmp/headlamp-render.yaml

echo "--- must be view, not cluster-admin ---"
grep -A3 'kind: ClusterRoleBinding' /tmp/headlamp-render.yaml | grep 'name: view'
echo "--- must have an HTTPRoute ---"
grep -c 'kind: HTTPRoute' /tmp/headlamp-render.yaml
echo "--- must have no Ingress ---"
grep -c 'kind: Ingress' /tmp/headlamp-render.yaml || echo "0 (good)"
echo "--- must have no oidc Secret ---"
grep -c 'name: oidc' /tmp/headlamp-render.yaml || echo "0 (good)"
echo "--- must have resource requests ---"
grep -A4 'resources:' /tmp/headlamp-render.yaml | grep -E 'cpu|memory'
echo "--- image must resolve to the chart appVersion ---"
grep 'image: ' /tmp/headlamp-render.yaml
```

Expected: `name: view` present; HTTPRoute count 1; Ingress count 0; oidc count 0; requests
show `cpu: 10m` and `memory: 64Mi`; image reads `ghcr.io/headlamp-k8s/headlamp:v0.45.0`.

Any one of these failing means the values file is wrong. Fix before committing.

- [ ] **Step 5: Server-side dry-run the rendered output**

```bash
kubectl create namespace headlamp --dry-run=client -o yaml | kubectl apply -f - --dry-run=server
kubectl apply -f /tmp/headlamp-render.yaml --namespace headlamp --dry-run=server
```

Expected: every object reports `(server dry run)`. The HTTPRoute is the one to watch. A
rejection here means the `homelab` Gateway in `envoy-gateway-system` does not accept this
route.

- [ ] **Step 6: Commit**

```bash
git add apps/headlamp/app.yaml apps/headlamp/values.yaml
git commit -m "feat(headlamp): add chart source and values

No login and read-only RBAC together: the gateway VIP is RFC1918, so reaching
the UI already requires the LAN or the tailnet.

image.tag left unset on purpose - an explicit tag survives Helm upgrades and
would let the release report a new chart version while running an old image."
```

### Task 2: Read-only RBAC for CRDs

Built-in `view` covers the core group, `apps`, `batch` and `cert-manager.io` only. Every other
CRD in this cluster is denied, which would leave Headlamp showing a generic dashboard with no
Applications, Longhorn volumes, Postgres clusters, HTTPRoutes or VPAs.

**Files:**
- Create: `apps/headlamp/rbac.yaml`

**Interfaces:**
- Consumes: the ServiceAccount `headlamp` in namespace `headlamp`, created by Task 1.
- Produces: ClusterRole `headlamp-read` and ClusterRoleBinding `headlamp-read`. Names must not
  collide with the chart's own `headlamp-admin` binding.

- [ ] **Step 1: Prove the gap exists before fixing it**

```bash
kubectl get clusterrole view -o json \
  | python3 -c "
import json,sys
groups={g for r in json.load(sys.stdin)['rules'] for g in r.get('apiGroups',[])}
for want in ['argoproj.io','longhorn.io','postgresql.cnpg.io',
             'gateway.networking.k8s.io','monitoring.coreos.com',
             'autoscaling.k8s.io','cilium.io']:
    print(f'{want:34} {\"covered\" if want in groups else \"DENIED\"}')
"
```

Expected: all seven report `DENIED`. This is the condition Task 2 exists to fix. If any
reports `covered`, an operator has since labelled its CRDs for view aggregation and the group
can be dropped from the list below.

- [ ] **Step 2: Regenerate the API group list against the live cluster**

The list below was captured on 2026-09-20. Confirm it still matches before trusting it:

```bash
kubectl api-resources --no-headers 2>/dev/null \
  | awk '{print $(NF-2)}' | grep -v '^$' | sed 's|/.*||' | sort -u | grep -v '^v1$'
```

Expected: 40 groups. If the cluster has gained one since, add it to the role in Step 3.

- [ ] **Step 3: Write `apps/headlamp/rbac.yaml`**

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: headlamp-read
# Secrets exist only in the core group, which the chart's `view` binding covers
# and this role omits. Wildcarding non-core groups reads everything but Secrets.
# A new operator's CRDs stay invisible until its group is added here.
rules:
  - apiGroups:
      - acme.cert-manager.io
      - admissionregistration.k8s.io
      - apiextensions.k8s.io
      - apiregistration.k8s.io
      - apps
      - argoproj.io
      - authentication.k8s.io
      - authorization.k8s.io
      - autoscaling
      - autoscaling.k8s.io
      - batch
      - bitnami.com
      - cert-manager.io
      - certificates.k8s.io
      - cilium.io
      - coordination.k8s.io
      - discovery.k8s.io
      - events.k8s.io
      - externaldns.k8s.io
      - flowcontrol.apiserver.k8s.io
      - gateway.envoyproxy.io
      - gateway.networking.k8s.io
      - gateway.networking.x-k8s.io
      - helm.cattle.io
      - k3s.cattle.io
      - longhorn.io
      - metrics.k8s.io
      - monitoring.coreos.com
      - monitoring.grafana.com
      - networking.k8s.io
      - nfd.k8s-sigs.io
      - node.k8s.io
      - policy
      - postgresql.cnpg.io
      - rbac.authorization.k8s.io
      - resource.k8s.io
      - scheduling.k8s.io
      - secrets.infisical.com
      - storage.k8s.io
      - tailscale.com
    resources: ["*"]
    verbs: ["get", "list", "watch"]
  # Cluster-scoped storage objects `view` withholds. Without these the Storage
  # section renders empty.
  - apiGroups: [""]
    resources: ["persistentvolumes"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: headlamp-read
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: headlamp-read
subjects:
  - kind: ServiceAccount
    name: headlamp
    namespace: headlamp
```

- [ ] **Step 4: Assert the role grants no Secret read**

```bash
python3 -c "
import yaml
docs=[d for d in yaml.safe_load_all(open('apps/headlamp/rbac.yaml')) if d]
role=[d for d in docs if d['kind']=='ClusterRole'][0]
for r in role['rules']:
    if '' in r['apiGroups']:
        assert 'secrets' not in r['resources'], 'core rule grants secrets'
        assert '*' not in r['resources'], 'core rule wildcards, which includes secrets'
    assert set(r['verbs']) <= {'get','list','watch'}, f'write verb in {r[\"verbs\"]}'
print('OK: read-only, no Secret access')
"
```

Expected: `OK: read-only, no Secret access`. This is the check that catches a later edit
widening the core rule to `*`, which would silently hand every Secret in the cluster to an
unauthenticated page.

- [ ] **Step 5: Server-side dry-run**

```bash
kubectl apply -f apps/headlamp/rbac.yaml --dry-run=server
```

Expected: both objects report `(server dry run)`. A rejection means a group name is
misspelled or the ServiceAccount subject is malformed.

- [ ] **Step 6: Commit**

```bash
git add apps/headlamp/rbac.yaml
git commit -m "feat(headlamp): grant read on non-core API groups

Built-in view covers core, apps, batch and cert-manager only, so every CRD in
this cluster was denied: no Applications, Longhorn volumes, Postgres clusters,
HTTPRoutes or VPAs would have rendered.

Secrets exist only in the core group, so wildcarding the non-core groups reads
everything but Secrets."
```

### Task 3: VerticalPodAutoscaler

**Files:**
- Create: `apps/headlamp/vpa.yaml`

**Interfaces:**
- Consumes: the Deployment `headlamp` from Task 1.
- Produces: nothing other tasks depend on.

- [ ] **Step 1: Write `apps/headlamp/vpa.yaml`**

Matches the repo pattern in `apps/bazarr/vpa.yaml`:

```yaml
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: headlamp
  namespace: headlamp
spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: headlamp
  updatePolicy:
    updateMode: "InPlaceOrRecreate"
  resourcePolicy:
    containerPolicies:
      - containerName: "*"
        minAllowed:
          cpu: 10m
          memory: 64Mi
        maxAllowed:
          cpu: 1
          memory: 512Mi
```

`maxAllowed` is lower than the repo's usual 2 CPU / 2Gi. Headlamp proxies API reads and
serves static assets. It has no transcode, no database and no import queue, so a ceiling that
high would only mask a runaway.

- [ ] **Step 2: Confirm the targetRef name matches what the chart renders**

```bash
grep -A2 '^kind: Deployment' /tmp/headlamp-render.yaml | grep 'name:'
grep -A3 'targetRef' apps/headlamp/vpa.yaml | grep 'name:'
```

Expected: both print `name: headlamp`. A VPA pointed at a Deployment that does not exist is
silently inert, which is the failure this step catches.

- [ ] **Step 3: Server-side dry-run**

```bash
kubectl apply -f apps/headlamp/vpa.yaml --dry-run=server
```

Expected: `verticalpodautoscaler.autoscaling.k8s.io/headlamp created (server dry run)`.

- [ ] **Step 4: Commit**

```bash
git add apps/headlamp/vpa.yaml
git commit -m "feat(headlamp): add VPA

Ceiling set below the repo default: Headlamp proxies API reads and serves
static assets, so 2 CPU / 2Gi would mask a runaway rather than bound one."
```

**Files:**

**Interfaces:**
- Consumes: the hostname from Task 1.
- Produces: nothing other tasks depend on.

- [ ] **Step 1: Add the target to the `apps` Probe**

Insert `- https://headlamp.nik-homelab.dev` into the `staticConfig.static` list of the Probe
named `apps`, keeping the existing alphabetical grouping. It belongs in `apps`, which uses the
`http_2xx` module, not `apps-auth`: Headlamp answers 200 unauthenticated, so the 401-tolerant
module would weaken the assertion for no reason.

No comment. The surrounding targets carry none, and the reasoning lives in this plan and the
commit.

- [ ] **Step 2: Confirm the module follows redirects**

```bash
grep -A5 'http_2xx:' system/blackbox-exporter/values.yaml | grep follow_redirects
```

Expected: `follow_redirects: true`. This is why a redirect off `/` will not produce a standing
`EndpointDown` the moment the probe lands. If it ever reads `false`, this target needs the
`http_2xx_auth` module instead.

- [ ] **Step 3: Server-side dry-run**

```bash
kubectl apply -f system/blackbox-exporter/probes.yaml --dry-run=server
```

Expected: all three Probes report `configured (server dry run)`.

- [ ] **Step 4: Commit**

```bash

git commit -m "feat(headlamp): probe the UI for reachability

Headlamp exposes no metrics, so a blackbox probe is the whole monitoring
story. http_2xx rather than http_2xx_auth: it answers 200 unauthenticated,
and the 401-tolerant module would weaken the assertion."
```

### Task 5: Merge and verify live

The apps ApplicationSet tracks `main`, so nothing above has reached the cluster. This task is
where the two behaviors the spec could not verify offline get settled.

**Files:** none. This task merges and observes.

**Interfaces:**
- Consumes: everything from Tasks 1 through 4.
- Produces: a running Headlamp.

- [ ] **Step 1: Review the full branch diff**

```bash
git diff main...HEAD
```

Expected: four new files under `apps/headlamp/` and one added line in
`system/blackbox-exporter/probes.yaml`. Anything else does not belong in this change.

- [ ] **Step 2: Open the PR**

```bash
git push -u origin feat/headlamp
gh pr create --fill
```

- [ ] **Step 3: Merge, then force the ApplicationSet to discover the new directory**

A new `app.yaml` needs the ApplicationSet to re-run its git file generator. An Application-level
refresh will not find it, because the Application does not exist yet.

```bash
gh pr merge --squash --delete-branch
kubectl annotate applicationset apps -n argocd \
  argocd.argoproj.io/application-set-refresh=true --overwrite
kubectl get application headlamp -n argocd
```

Expected: the `headlamp` Application exists within about a minute.

- [ ] **Step 4: Wait for the sync to land**

```bash
kubectl wait --for=jsonpath='{.status.sync.status}'=Synced \
  application/headlamp -n argocd --timeout=300s
kubectl get application headlamp -n argocd \
  -o custom-columns=SYNC:.status.sync.status,HEALTH:.status.health.status
```

Expected: `Synced` and `Healthy`. On failure read
`kubectl get application headlamp -n argocd -o jsonpath='{.status.conditions}'` before
changing anything.

- [ ] **Step 5: Confirm the pod is running with the requests it was given**

```bash
kubectl get pods -n headlamp
kubectl get pod -n headlamp -l app.kubernetes.io/name=headlamp \
  -o jsonpath='{.items[0].spec.containers[0].resources}'
```

Expected: one Running pod, and resources showing `cpu: 10m` / `memory: 64Mi` requests. Empty
resources means the values file did not apply.

- [ ] **Step 6: Verify the RBAC boundary from both sides**

```bash
SA=system:serviceaccount:headlamp:headlamp
echo "must be no:"
kubectl auth can-i get secrets --as="$SA" -A
kubectl auth can-i delete pods --as="$SA" -A
echo "must be yes:"
kubectl auth can-i list applications.argoproj.io --as="$SA" -n argocd
kubectl auth can-i list volumes.longhorn.io --as="$SA" -A
kubectl auth can-i list httproutes.gateway.networking.k8s.io --as="$SA" -A
kubectl auth can-i get pods --as="$SA" -A
```

Expected: the first two print `no`, the last four print `yes`. This is the single most
important check in the plan. A `yes` on secrets means an unauthenticated page can read every
credential in the cluster, and the correct response is to revert the merge, not to debug
forward.

- [ ] **Step 7: Load the UI and settle the open question**

Open `https://headlamp.nik-homelab.dev` from the LAN or the tailnet.

Expected: the cluster view loads. The spec records one genuine unknown here: whether
`-unsafe-use-service-account-token` skips the sign-in screen outright or still presents a
cluster picker. Either outcome is acceptable. Record which one happened in the PR, because the
spec claims it is unverified.

Also check, via browser devtools or page source, whether the ServiceAccount token is
retrievable from the page. The flag likely exposes it to the browser, and a token lifted from
the page would work from outside the RFC1918 boundary the spec names as the only access
control. Blast radius stays read-only, so record this as a known answer, not an assumption.

Then confirm in the UI:
- An ArgoCD Application and a Longhorn volume both render. This is what plain `view` would
  have failed.
- Opening a Secret returns a permission error rather than a value.

- [ ] **Step 8: Confirm the probe went green rather than red**

```bash
kubectl exec -n monitoring-system sts/prometheus-monitoring-system-kube-pro-prometheus -c prometheus -- \
  wget -qO- 'http://localhost:9090/api/v1/query?query=probe_success{instance="https://headlamp.nik-homelab.dev"}' \
  | python3 -m json.tool
```

Expected: one result with value `1`. A `0` means the probe is about to raise `EndpointDown`,
and Step 2 of Task 4 is where to start reading.

- [ ] **Step 9: Confirm Homepage picked up the annotations**

Open `https://home.nik-homelab.dev`. Expected: a Headlamp tile under Infrastructure with its
icon rendering.

- [ ] **Step 10: Close out**

Move the Linear issue to Done now, not at merge. The repo's rule is that an issue closes when
the change is live, and Step 7 is the first moment that is true.

## Rollback

Delete `apps/headlamp/` and revert the `probes.yaml` line, then merge. ArgoCD prunes the
namespace, the Deployment and both ClusterRoleBindings. The `headlamp-read` ClusterRole is
cluster-scoped but lives in the app directory, so it prunes too. No data survives because none
exists.
